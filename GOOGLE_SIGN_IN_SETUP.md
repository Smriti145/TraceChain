# Google Sign-In setup for TraceChain

Google Sign-In is implemented for the operations website and Android customer app, but it stays unavailable until your own Google Cloud OAuth client is configured. Do not commit any client secret, service-account JSON or `.env` file. A Web **client ID** is public and can be configured in Render.

1. In [Google Auth Platform](https://console.cloud.google.com/auth/overview), select your project, complete Branding (app name, support email, authorized domain) and Audience. While Audience is in Testing, add the Google accounts that will test the demo.
2. Create an OAuth client of type **Web application**. Add authorized JavaScript origin `https://tracechain-mvp.onrender.com`. For local browser tests, also add `http://localhost:5001`. This project uses the Google Identity Services JavaScript callback, so no redirect URI is required for the web flow.
3. Copy the Web client ID (ending `.apps.googleusercontent.com`) into the Render service's **Environment** as `GOOGLE_WEB_CLIENT_ID`. It is not a client secret. Redeploy the service. Check `https://tracechain-mvp.onrender.com/api/auth/google/config`: it should return the client ID.
4. Create a second OAuth client of type **Android** with package name `com.mobile` and the signing certificate SHA-1 for the APK you will test. The current mentor APK is debug-key signed, and its SHA-1 is `5E:8F:16:06:2E:A3:CD:2C:4A:0D:54:78:76:BA:A6:F3:8C:AB:F6:25`. Confirm your own artifact with `keytool -list -v -keystore mobile/android/app/debug.keystore -alias androiddebugkey -storepass android -keypass android`. A future privately signed production APK requires another Android OAuth client or fingerprint for its own keystore.
5. Merge/deploy this feature (Prisma migration runs on Render startup), then build a **new** Android APK with `cd mobile && npm run android:release`. The previous APK cannot gain new native Google Sign-In code without rebuilding. Test a personal Google account, not a shared demo address.

New Google users and all public password registrations are assigned `CUSTOMER`. An existing password account with the same email must first sign in with its password and explicitly link Google from its account; matching email alone never grants a role. Shared `@tracechain.demo` accounts cannot link personal Google accounts. Staff roles still need a secure, separate provisioning/invitation workflow. Do not remove existing demo logins until that workflow is ready and the mentor has replacement accounts.

Google sign-in on **iOS is not yet configured**: it additionally requires an iOS OAuth client ID, URL scheme and a native build. Email/password login on iOS remains available.
